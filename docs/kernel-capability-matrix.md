# Kernel capability and validation matrix

Source review of the four vendored-by-reference AAH20 kernels at the revisions below. The code was inspected from read-only checkouts; this document does not claim a benchmark win, an exact solution to an NP-hard problem, or that the upstream labels are independently certified. The HTTP runtime uses a 45-second job timeout and explicit graph limits; each callable remains a heuristic or specialized routine with the boundaries below.

| Kernel and pinned revision | Observed behavior and integration safeguards |
| --- | --- |
| `graph-rag-kernel` — [`35b1bb93a04d419fc1167480d93a1eed711fb711`](https://github.com/AAH20/graph-rag-np-hard-kernel/tree/35b1bb93a04d419fc1167480d93a1eed711fb711) | `HierarchicalCommunityDetector.solve(max_iterations=50)` starts with one community per node and greedily moves nodes when computed modularity gain is positive. It iterates input node order, so node permutations can change the result; it has a fixed iteration cap and does not implement hierarchical aggregation despite its class/module wording. Edges whose endpoints are absent from the supplied node set are ignored. Zero-weight/edgeless or singleton input returns all nodes in one community with modularity 0. Validate IDs/weights and compare objective values across permutations; do not treat the output as a global optimum. Source: `graph_rag_np_hard_kernel/core/community_detection.py`. |
| `agentic-kernel` — [`ad8e99faa20c414b60d86b8ec211863c003535fc`](https://github.com/AAH20/agentic-np-hard-kernel/tree/ad8e99faa20c414b60d86b8ec211863c003535fc) | `WorkflowDAGSynthesizer.solve()` applies Kahn topological ordering and earliest/latest-time passes, which is CPM scheduling for valid DAG input. It does not validate dependency IDs: unknown dependencies count in `in_degree` but do not create successor links. Cycles trigger a fallback that appends unresolved IDs from a set, so ordering is not deterministic and the returned schedule is not a valid DAG solution. Reject unknown dependencies/cycles before relying on timing or critical path. Source: `agentic_np_hard_kernel/core/workflow_dag.py`. |
| `mirofish-optimizer` — [`d2a3df25cf80750fadd562373f7941b9cb8db2f1`](https://github.com/AAH20/mirofish-swarm-optimizer/tree/d2a3df25cf80750fadd562373f7941b9cb8db2f1) | `InfluenceMaximizer.solve(k_seeds=3,num_samples=1000)` builds reverse-reachability samples with hard-coded `random.Random(42)` and greedy coverage. This is a deterministic sampled estimate for a fixed input/order, not an exact cascade expectation; sample count controls approximation effort. `rng.choice(self.nodes)` fails for an empty population when samples are requested. The kernel adapter has a smaller input cap; additionally validate nonempty agents and edge probabilities in [0,1] before calling. Source: `mirofish_swarm_optimizer/core/influence_maximizer.py`. |
| `graph-swarm-kernel` — [`d429ee702e0e9b59b68f3714723a4f1d4bc425c8`](https://github.com/AAH20/agentic-graph-swarm-kernel/tree/d429ee702e0e9b59b68f3714723a4f1d4bc425c8) | `solve_epistemic_consensus()` groups normalized subject/predicate pairs and selects the object with greatest summed reputation × confidence. This resolves direct object conflicts, but it does not check graph acyclicity; its result sets `cycle_free_certified=True` unconditionally, including empty input. Treat that field as untrusted and independently validate cycles/constraints before consuming the graph. Sources: `agentic_graph_swarm_kernel/core/epistemic_consensus.py`, `core/models.py`. |

## Small, reproducible evaluation fixtures

- **Communities:** empty and disconnected graphs, a small planted-partition graph, and the same graph under several node-order permutations. Check edge/node validity, modularity computed by an independent implementation, and partition agreement (for example adjusted Rand index); compare runtime against a simple connected-components and degree-based baseline. Report order sensitivity.
- **Workflow DAG:** chain, fork, and diamond DAGs with known critical path; then inject an unknown dependency and a cycle. For the valid tiny cases, compare makespan with exhaustive enumeration or an independent CPM implementation. Require malformed inputs to be rejected before a schedule is reported.
- **Influence:** a tiny fixed-probability graph where seed-set cascade expectations can be enumerated exactly, plus empty and disconnected cases. Hold seed count and sample budget constant; report estimated spread, absolute error against enumeration, variability over independent reference seeds, and runtime alongside random/degree baselines.
- **Consensus:** duplicate support, conflicting objects, and a directed cycle across accepted facts. Measure contradiction loss and independently run a cycle detector; reject/flag cyclic output regardless of `cycle_free_certified`.

For any “surpass” comparison, pin inputs and revisions, first require valid/feasible outputs, then compare objective or approximation error on exact small references. Also report quality, latency, memory, and sensitivity across input permutations/seeds against simple baselines under the same compute budget. Include repeated-run confidence intervals where sampling is involved. Do not compare unlike objective values or infer general superiority from a single fixture.
